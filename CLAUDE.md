# Dexter — Project Conventions

Static HTML/CSS/JS, no framework, no build step. Opened as local files, not server-hosted. All asset paths are relative.

- `project.html` — the single-project dashboard shell (Dashboard/Tasks/Files screens + every overlay). Always parameterized via `?project=<id>` (`marigold`, or `new&name=&client=` for a fresh one) — the markup itself carries no default/fallback project content; everything project-specific is written in by JS from `assets/js/project-data.js`'s `activeProject`.

## CSS conventions
- No `w-` prefix — plain semantic class names (e.g. `navbar`, `task-body`), not Webstudio-style prefixed/numbered ones
- No bare element selectors except `:root`, `*`, `body`
- No hardcoded colors. Every color is a CSS custom property in `:root`, with a `body[data-theme="light"]` override wherever the dark-mode value wouldn't read correctly on a light background (borders, hover fills, overlay tints, shadows included — not just brand/semantic colors)

## Standing UI conventions
- **Inline expand, not overlay.** Default to expanding content in place — an accordion/inline-grow within the existing layout — rather than opening a modal or full overlay. Three independent decisions converged on this pattern (task list items, file previews in Files-screen Grid view, and the new Timeline feed's cards — see `dexter-technical-briefing.md`), so treat it as the standing default for any future feature that needs to show more detail on click, not a one-off per feature. A genuine overlay (the settings panel, the email-draft review, task creation) is still fine where the content is a distinct action/form rather than "more detail on the thing I just clicked."
- **Page vs. overlay.** Confirmed 2026-07-19, see `dexter-technical-briefing.md`'s "Page architecture." A **page** is a top-level "where am I" mode — reload-safe, bookmarkable, and representing a fundamentally different state, not a detail view of something else (`landing.html`, `login.html`, `index.html`, `project.html`, and a flagged-but-not-yet-built account/settings page). An **overlay** only makes sense in the context of a page already loaded — closing it returns you to exactly where you were, and it never needs its own URL. When adding something new that needs its own "home," check it against this rule before defaulting to either shape.

## Product context (short version)
Dexter is an agentic project companion for freelancers. Support without takeover: the agent never takes final decisions away from the user.

**Scope, updated 2026-07-23:** this is an active, ongoing project, not a fixed-length sprint toward one demo date. Superseded: the earlier framing of "showcase prototype for a focus group at end of month," and `docs/handoff.md`'s "4-Week Showcase Sprint" plan/title. The target is now general user testing and a full showcase — build and design decisions should hold up under broader, less-curated usage than a single moderated focus-group session, not just "good enough for a demo." This doesn't loosen the MVP boundaries below (still no full email/calendar/CRM/invoicing/team collaboration) — it raises the bar on quality and reliability within whatever IS being built.

**Final product release date: September 2, 2026** (added 2026-07-23). Not a rushed short sprint deadline — roughly six weeks out from when this was set — but a real one: prioritize accordingly, and don't treat "we have time" as license to under-scope quality/reliability work given the general-testing bar above.

**Claude MCP connector — real and restart-proof as of 2026-07-24.** `claude-mcp-server/` (see its own README and `dexter-technical-briefing.md`'s "Claude MCP access") gives Cowork a genuine per-project connection: its own URL and its own passphrase per project (Settings → "Claude (Cowork)"), and the connection now survives a server restart with no manual reconnect — two real SDK-integration bugs (a 500-instead-of-401 on an expired token, a 400-instead-of-404 on an unrecognized session) were found and fixed to get there, both live-tested, not just reviewed. A `dexter_rename_project` tool exists on both `mcp-server/` and `claude-mcp-server/`. The demo project used to test all of this is renamed from "Demo Project" to **"Dexter Dev."** Testing the rename live also caught and fixed a real, unrelated sync bug: `POST /projects/:id/client-state` had no protection against a browser tab's stale local cache overwriting a newer server-side change — see `dexter-technical-briefing.md`'s "Discrete-action refactor" section for the fix (a `baseUpdatedAt` staleness check, general to every client-owned field, not just `name`).

**Gated edit/delete + activity backdating, 2026-07-24/25.** Eight new gated MCP tools now exist on `claude-mcp-server/`, all routed through the same propose/approve gate `dexter_propose_phase` used before it was ungated: six from 2026-07-24 (`dexter_edit_phase`/`dexter_delete_phase`/`dexter_edit_task`/`dexter_delete_task`/`dexter_edit_agent_task`/`dexter_delete_agent_task`) plus two more from 2026-07-25 (`dexter_edit_activity`/`dexter_delete_activity`). `dexter_log_activity`/`dexter_propose_phase` also gained an `occurred_at` param (both MCP servers) so a logged entry's displayed "when" can be backdated instead of always reading "Just now" — but that alone only helps entries logged going forward, which is why the two activity edit/delete tools exist too. See `dexter-technical-briefing.md`'s "Agent action gating" section for the full mechanics.

**Note on "everything is mocked":** true when this line was first written, no longer true across the board. Login and Google Drive file storage are designed as real integrations, not mocks — see `dexter-technical-briefing.md`'s "User accounts & login" and "Google Drive file storage" sections. Neither is built yet as of 2026-07-19. Treat "mocked unless noted otherwise" as the working assumption for anything not covered by those two sections.

## Working style
- Plan before large diffs (Plan Mode) for anything touching more than 2-3 files.
- After a refactor, verify it's visually/behaviorally identical before adding new features on top of it.
- Don't touch files outside `index.html`, `project.html`, `assets/`, `css/` unless asked.
- One task/feature per session — `/clear` between unrelated steps rather than carrying a long history forward.

**As of 2026-07-24, this project tracks its own progress on its own dashboard.** The "Dexter Dev" project (see the Claude MCP connector note above) is the live record of this repo's own build progress, via the Claude MCP connector, not just these markdown docs.
